## P1 — The read contract

**Commit:** `ee2de51` "cs041 p1: GDD read index + CLAUDE.md read contract"

GDD gains `## 0. How to read this document`, immediately after the title block and before §1: one
row per §2.x/§3.x subsection (35 rows), each carrying the section's own number and name verbatim,
an approximate size, and a "read this when you are touching…" line phrased as what a session might
be *editing*, not what the section is *called* — the difference between "§2.14 Powerups —
powerups" (useless) and "§2.14 — any pickup, any drop roll, the recycle hub's per-visit drop, the
powerup HUD rows, `powerBudget`" (actionable). Cross-cutting mechanics appear under every section
that owns a piece of them. §0 landed at 9.8 KB against a 3–4 KB target — a deliberate call, recorded
at the time: 35 rows leave ~90 bytes each at 4 KB, of which the number, name and size already spend
~55, leaving no room for a "touching…" line that isn't itself useless.

`CLAUDE.md`'s document map row for the GDD changes from "§1–§3 before code" to the named-subsection
contract stated once under the map: §0 + §1 always, then the §2.x/§3.x subsections the phase names,
explicitly still permitting "read the whole thing" when a phase is broad. GDD §5.1 item 5 carried a
second, independent statement of the old rule and was reworded to match — a second site for the same
rule change, not new content.

`CLAUDE.md` gains its own 50 KB ceiling, in the same region as `STATUS.md`'s existing cap, built on
the file's own header idiom ("states rules, not reasons; reasons live in `RATIONALE.md`") turned on
itself: past the threshold, an over-4-KB section moves its *reasoning* to `RATIONALE.md` under an
anchor and keeps its *rule* in place. The 50 KB number was recorded as a first guess (FLAG-CS041-b).

## P3 — The staleness rule, the audit, and §3

**Commit:** `511a768` "cs041 p3: staleness rule + identifier audit + §3 sweep"

The staleness rule, as applied: **remove** a sentence only if it is false about the current build —
names a deleted identifier as live, describes machinery that no longer exists, states a tuning rule
whose knobs are gone, or contradicts a `CLAUDE.md` ⛔/⚠ or a later GDD section. **Keep** everything
merely *old* — narration, phase attribution, multi-hop retune chains, "as of CSxxx," protective
history — however wordy, and keep every "X was deleted" sentence, since that statement is both true
and precisely the kind of thing the audit exists to surface as a candidate, not a verdict.

The audit shipped as a committed, reporting-only tool: `scratchpad/gdd-audit.py`, extracting the
build's `<script>` block, stripping comments and string literals with a character scanner (never a
regex — the same reasoning `CLAUDE.md`'s Test rules give for `_harness.js`'s comment handling), and
reporting every backticked GDD identifier with zero live build occurrence, per section. It is not
wired into `run-all.js`.

Applied to GDD §3's table (everything but P2's already-done Constants row): **six of twelve
candidate-carrying rows were wrong; five were fixed by correction, not removal.** §3: 75,608 →
75,451 bytes, a net **−157** — the shape of a correctness sweep, not a trim. The largest single cut:
the Helpers row's five paragraphs specifying `difficultyFactor`/`ramp`/`leverScale`/`cycleValue`/
`wavePressure`/`bonusSpawnChance` (2,915 → 1,497 bytes), one of which actively instructed a future
session to "use these for any new wave-scaled value" — a live-sounding lie. §3's ⛔ count rose
**13 → 22** (nine new "X is GONE" prohibitions added); ⚠ unchanged at 1; **no marker removed.**

Two false-positive classes were documented for the first time here, in `log/GDD-TRIM-CS041.md`'s
header: identifiers held only as **string literals** (`debugOverride` reads as dead because the
scanner correctly strips `const DEBUG_OVERRIDE_ID = "debugOverride"`'s string contents), and **name
collisions** (`ramp` shows four live hits that are all a local arrow function inside
`AudioSys.lowhpSet`, while the difficulty-era `ramp()` really is gone). Suite: 171/171, 0 skips.

## Headline number

**This changeset's headline is the per-session read contract, not either byte total above** — it
was already true at P1 and the sweep (P3–P5) did not change it:

**Old rule (§1–§3 before code): ~505 KB per session. New rule (§0 + §1 + the subsections a phase
actually names): ~33–46 KB for a representative phase.** A ~91–94% reduction, with nothing deleted —
every byte the old rule loaded still exists in the file, findable by name, just no longer forced
onto every session regardless of what it touches.

**The sweep's own headline, separately:** across P3–P5, the identifier audit generated **~246
candidates** (105 + 41, plus P3's ~100 against §3 alone) of which **16 were real** (9 + 7) — a
~93–94% false-positive rate, confirmed exactly as GATE C predicted from its own 156-identifier
