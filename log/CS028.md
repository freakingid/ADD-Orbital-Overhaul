# CS028 — the satellite breakup model

Twelve real, named spacecraft replace the six generic `SAT_ART` archetypes; a body now carries
its craft/piece identity through its own destruction instead of re-rolling art at every split;
the retired per-craft `small` field is replaced by a craft-agnostic `SAT_SCRAP` table. One phase
(P1) built it, gated on four playtest questions; P2 applied the gate's answers and closed.

## P1 — data shape, identity propagation, split-site rewrite

`SAT_ART` replaced end to end (6 generic archetypes → 12 real craft: Sputnik 1, Vanguard 1,
Explorer 1, Telstar 1, Syncom, Hubble, JWST, Voyager, Pioneer 10, Juno, Apollo LM, Skylab), each
`{ full, pieces[3] }`. New top-level `SAT_SCRAP` (3 craft-agnostic shards) owns the small tier.
`DebrisSatellite`'s constructor takes two optional args (`craft`, `piece`, both defaulting to the
`-1` sentinel) and dispatches: size 3 → rolled craft's `full`; size 2 → the *passed* craft's
`pieces[piece % 3]`; size 1 → a random `SAT_SCRAP` shard with both fields left at `-1`.
`destroyDebris()` passes `a.craft` and `pieceOffset + i` to every child. FORK-CS028-A shipped as
the rotating offset (`Math.floor(rand(0, 3))`, once per kill) — open at the gate, since resolved
(see below).

Measured, not assumed: 12 craft / 3 pieces each / worst authored `|p|` **0.9879** (Apollo LM piece
2) / max `full` polylines **10** (the LM) — all matching the plan's figures. 600 real
`destroyDebris()` splits across **both** `junkSplit` values (300 at level 1, 300 at level 15):
600/600 craft inherited, 600/600 pieces in range, 600/600 distinct. `scratchpad/test-cs028-p1.js`
delivered, 44 assertions. Mutation-checked: swapping the offset for a fixed `i`, or dropping craft
inheritance, each fails the suite.

**Suite: 110 files, 110 passed, 0 failed, 0 skipped**, two consecutive runs, diff confined to
wall-clock timings. The two non-split call sites (wave spawner ~6328, title decoration ~9887) are
unedited — exactly three `new DebrisSatellite(` sites, as the plan said.

**FLAG-CS028-a — the art's authoring tool is not in the repo.** `IMPLEMENTATION-PHASES-CS028.md`
Step 6 named `tools/sat-art-lab.html` as the generator; it does not exist (`tools/` holds
music/scoop/voice/voice-robot labs only), so Step 6's cosmetic CS027→CS028 relabel had no target
and was skipped. `SAT_ART`/`SAT_SCRAP` are currently their own source of truth — a retune or a
13th craft has no instrument. Not blocking; the table is validated in-suite.

## P2 — the closing phase: gate answers applied, version 1.0.0.28

Four playtest questions gated P1 → P2 (`PLANNED-FEATURES-CS028.md` §5). Paul's answers:

1. **FORK-CS028-A (rotating vs. fixed piece index).** Rotating is good — no code change; the
   shipped rotating offset stands.
2. **FLAG-CS028-b (jitter vs. regular geometry).** Use the per-polyline `jitter: false` opt-out.
   Added: `SAT_ART[3]` (Telstar)'s facet/belt straight-line polylines (the equatorial grid lines in
   `full` and the matching lines in pieces 0/1) and `SAT_ART[6]` (JWST)'s two sunshield-layer
   outlines plus the hex-mirror seam lines (in `full` and piece 0) now bake with zero wobble. The
   constructor's art-bake step reads `pl.jitter === false ? 0 : jit` per polyline instead of one
   shared `jit` for the whole craft. Tear/damage lines and outer silhouettes were left jittered —
   only the repeating regular geometry the gate flagged.
3. **Piece distinctness (Hubble 1/2, Skylab 0/2, Juno's folded blade — same vertex-count
   signature).** Leave as is — not a P2 edit; any real art rework is its own changeset.
4. **Spawn dilution (12 craft, ~8.3%/kill vs. the old 16.7%).** Fine, read-only — no code change.

**Suite: 110/110 passed** after the jitter opt-out. `test-cs028-p1.js`'s art-bake bound assertion
(`mx <= radius * 1.08`) still holds — `jitter: false` only *reduces* wobble, never exceeds the
existing bound — so it needed no edit.
