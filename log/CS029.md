# CS029 — the rename, the game-over exit, and the delivery-floater dock anchor

Three jobs, deliberately kept in one changeset because none of them touches persistence,
difficulty, or the sim: a file rename, a readability fix at game over, and the delivery
floater column. Five phases: P1 rename, P2 game-over exit, P3 float lab, a blocking gate, P4
floater implementation, P5 close.

## The CS026 P6 misinterpretation, and why it mattered

CS026 P6 moved the delivery `"+pts"` floaters off the popped chain node (which could be up to
24 links behind the ship on a full haul) and read Paul's gate answer — *"it needs to be closer
to the ship"* — as a request for a ship-relative origin. The floaters shipped spawning at
`game.ship.x, game.ship.y − DELIVERY_FLOAT_DY`, a fixed 22px nudge above the hull, and a ⛔
comment block at `DEBUG.deliveryFloatRise` recorded the arithmetic (`160 × 0.05 = 8px` nominal
separation, ~10.7px measured) and the instruction that the offload cadence, not a bigger rise,
was the only safe lever if the column ever needed opening up.

That reading was wrong. Paul's actual intent, surfaced when CS029 planning revisited the
column, was a **static anchor at the dock** — not "closer to the ship," but "not tied to a
ship that keeps moving." The historical record stayed accurate to what was said (the CS026
gate answer, read literally, does support a ship-relative fix), which is exactly why it
couldn't simply be deleted once corrected: the comment justified real, working code for three
changesets, and silently erasing it would make the next person re-derive the same dead end.
§0.3 of `PLANNED-FEATURES-CS029.md` records the correction; §6.5 made rewriting the two
affected comment blocks (rather than deleting them) a mandatory P4 deliverable.

## P1 — the rename

`asteroids-deluxe.html` → `orbital-overhaul.html`, via `git mv` so history follows the file.
The planning estimate ("22 git-history sites, seven `git show` reads") undercounted by 3× — the
live count was 22 git-history sites across 18 files, plus `_phase-ref.js`'s own
`parentSource()`, plus one `git diff` pathspec site (§2.3). ~100 scratchpad test files also
hardcoded the live build path and broke the instant the file moved; all were swept. The 16
historical-SHA reads kept the legacy filename on purpose (they're reading what the repo
actually looked like at that commit) and are SETTLED-marked; `_phase-ref.js`'s `SCOPE_BASE` now
carries both names permanently. `FLAG-CS029-a` (the `test-cs024-p6b.js` pathspec spanning the
rename) was run, not assumed — git's rename detection held, `-U0` hunk structure intact,
315/315 in that file. Full suite: 111/111 passed, 0 failed, 0 skipped post-commit.

## P2 — the game-over exit path

§0.1's read found the defect wasn't a missing menu — `MENU_ROOT_OVER`, `rootItems()`,
`openPause()`/`closePause()` already routed game-over correctly. It was a legibility failure:
the one hint (`"MENU: O    (controller: B)"`) sat 14px, dim gold, static, 48px off the bottom
edge, directly under a 22px blinking neighbour, and named a key (`O`) no player would guess.
The one-line input guard now admits `game.state === "gameover"` alongside `"playing"`, carrying
the standing `!game.entry` operand. `drawMenuHint` gained a trailing optional `size` parameter
(default `MENU_HINT_SIZE`); all 9 pre-existing call sites stay byte-identical. The game-over
screen's two retired lines (a blinking 22px "play again" + a dim 14px hint) collapse to one
`drawMenuHint` call at `GAMEOVER_HINT_SIZE` (20, FORK-CS029-C, a playtest knob since this is the
only on-screen affordance rather than a reminder under a visible menu). New `test-cs029-p2.js`
drives the real keydown listener and `draw()` through a recording ctx (22/22). Full suite:
112/112 passed, 0 failed, 0 skipped.

## P3 — the float lab

`tools/dock-float-lab.html` (scoop-lab conventions, `file://`, no deps): a static dock, the real
offload cadence and point formula (`+50`…`+625` at 24), the two dock-anchored milestone
floaters, a dock/ship anchor toggle with a drifting mock ship, and three models (A/B/C) with the
specced knobs, replay/pause/step, and a run-minimum separation readout. Three things were
measured, not assumed: model B's §6.2 rule didn't have the property §4.3 claimed for it
(FLAG-CS029-c); the recorded "160 × 0.05 = 8px" separation was the ideal, not the shipped
number — actual on-screen separation is ~10.7px at 60fps quantisation (FLAG-CS029-d); and the
readout needed a second number, since the specced one (any two live floaters) pins near zero at
every milestone crossing regardless of model. Headlessly verified against the lab's own `sim()`
under stubs: model A bottoms out at 10.7px separation, model B holds `minGap` exactly at every
cadence tried, model C keeps one `+` floater alive and ticks `+50`…`+8100`. Build untouched;
suite 112/112, 0 failed, 0 skipped.

## P4 — model C shipped

`DELIVERY_FLOAT_DY` (the ship-relative nudge, and CS026 P6's own misreading — see above) is
retired. Both delivery branches — the towed one and the incidental one — now share one computed
anchor, `dock.y − DOCK_RADIUS × DELIVERY_FLOAT_ANCHOR_FRAC` (0.50): the dock is static for a
whole visit (`Dock.update()` only advances `spin`), so this is the fixed point Paul actually
asked for. The towed branch no longer pushes a floater per canister: one ticker
(`game.deliveryTicker`, held by reference) lives for the visit, its text rewritten per canister,
released as an ordinary floater at the last one. `FloatText` gained an optional `pinned` field
(default `false`; every pre-existing call site untouched) that holds position/life at birth
while `true`. A visit can end without a last canister — a hostile break, ship death, the
`comboGrace` timeout, or a fresh haul starting before the old one finished — so
`releaseDeliveryTicker()` runs at all five sites that zero `game.deliveryCount`, or an abandoned
ticker would sit pinned at the dock forever. The incidental branch is unchanged apart from the
shared origin — still its own floater, `COLOR.dim` at size 12, never folded into the ticker
(CS026 kept the two from sharing a tally on purpose, and CS029 preserves that split). Registry
holds at 85 — model C adds no knob. Both comment-debt sites named in §6.5 were rewritten, not
deleted. Seven pre-existing suite files that pinned the retired per-canister/ship-relative shape
were updated to match; their other claims (payment, latches, byte-identity) are untouched. New
`test-cs029-p4.js` drives the real offload/breakChain/scatterChain paths. Full suite: 113/113
passed, 0 failed, 0 skipped.

Carried, not resolved at P4: **FLAG-CS029-e** — at the gate's picked `anchorFrac` (0.50), the
lab measured model C's all-floaters minimum separation from the milestone floaters
(`SALVAGE BONUS`/`MAX HAUL`) at **0.0px** — zero clearance, not a crossing, but no air either.
Paul picked 0.50 anyway; it wasn't re-litigated at the gate. Recorded so a future "the ticker
looks like it's touching SALVAGE BONUS" report is recognised as this, not a new regression.
